- **Logging Guidelines**: Never use standard `print()` statements for console logging. Always use the `logger` package (e.g., `logger.i()`, `logger.e()`, `logger.d()`). Use the centralized logger instance defined in `lib/utils/app_logger.dart` whenever possible.
- **State Management & Riverpod Documentation**: Use Riverpod for all state management and storing context or data. Do NOT pass data through context or arguments from one page to another. Always write relevant and descriptive comments for Riverpod-related code (Providers, State classes, Notifiers, etc.) to explain their purpose and functionality.
- **Comprehensive Function Logging**: When creating or significantly modifying functions, always include logger statements at the beginning and end of the function. The start logger should log the function name and key arguments. The end logger should confirm successful execution and log the return value or the primary outcome of the function's internal logic. Use appropriate log levels (e.g., `logger.i()` for state changes or important outcomes, `logger.d()` for standard execution tracing).
- **Code Restructuring & Modularity**: Keep Widget build methods small and modular. Extract large widgets, forms, or dialogs into their own separate classes (e.g., `ConsumerStatefulWidget`). Break down complex widget trees into smaller builder methods prefixed with `// UI: `. Isolate business logic and state modifications into dedicated methods prefixed with `// Backend: ` to maintain a clean separation of concerns.
- **Non-Blocking External Services**: When invoking external services (like sending emails via `EmailService`) from within a synchronous UI flow or database update block, always wrap the external call in `Future.microtask(...)` and attach a `.catchError(...)` handler. This ensures the operation is executed as a completely non-blocking (fire-and-forget) background task, preventing slow external network requests from stalling the primary UI or data processing flow.
- **Static Analysis / Lint Checks**: Do not run `flutter analyze` or other static analysis command-line tools automatically after every file edit. Run these checks only at the end of a milestone, or when explicitly requested by the user.
